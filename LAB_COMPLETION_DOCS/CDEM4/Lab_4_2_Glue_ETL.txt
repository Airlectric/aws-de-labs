   └─ Cause: DenyUnencryptedObjectUploads bucket policy blocked Spark
             writes because Spark does not send the SSE header
   └─ Fix:   Added GlueServiceRole to ArnNotLike exclusion in
             bucket policy (consistent with DataSyncS3Role and
             KinesisFirehoseS3Role). Bucket default SSE-S3 still
             encrypts all writes automatically.

2. aws_s3_object folder placeholders failing on terraform apply
   └─ Cause: Same SSE header issue for daniel-admin IAM user
   └─ Fix:   Added server_side_encryption = "AES256" to all
             aws_s3_object resources in the S3 module

3. DataSync EC2 destroyed on re-apply
   └─ Cause: data "aws_ami" most_recent=true re-evaluated on each
             apply, new AMI ID triggered EC2 replacement
   └─ Fix:   Pinned AMI ID to ami-02b9a589195146a8f in datasync module

==============================================================
ETL PATTERNS LEARNED:
==============================================================
Pattern 1: Data Lake Zone Model
  raw/ (CSV, as-is) → processed/ (Parquet, cleaned) → curated/ (business-ready)

Pattern 2: Schema on Read
  spark.read.csv(..., inferSchema=True) — infer types at read time,
  flexible for messy data. Alternative: enforce schema on read (stricter).

Pattern 3: Idempotent Jobs
  df.write.mode("overwrite") — same result if run twice.
  Safe to re-run on failure. No duplicate data accumulation.

Pattern 4: Detailed Logging
  Print at each stage [1/3], [2/3], [3/3] — easy to debug failures
  in CloudWatch without downloading logs.
